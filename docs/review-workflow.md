# Воркфлоу ревью параграфа

Параграф проверяется **панелью редакторов** — несколько моделей параллельно,
каждая видит только свою ось качества. Это снижает «слепые пятна»: фактчекер не
отвлекается на стиль, стилист не лезет в механику платформы.

## Подготовка

1. Скопируйте `.env.example` → `.env` и заполните ключи нужных провайдеров:
   - `DEEPSEEK_API_KEY` — фактчек 1С
   - `OPENAI_API_KEY` — структура / метафоры / тон / стиль (роли GPT)
   - `GEMINI_API_KEY` — адверсар + читатель-первокурсник

   `.env` в git не попадает (см. `.gitignore`).

## Прогон

```bash
python3 scripts/review.py 2.4            # § по номеру → chapters/*/02-04_*.md
python3 scripts/review.py 2.4 --tone     # + редактор тона и ритма
python3 scripts/review.py 2.4 --style    # + редактор стиля и канона
python3 scripts/review.py chapters/02_semantika/02-04_perevod.md   # явный путь
```

Каждый редактор получает контекст книги: `CLAUDE.md`, `spec/constitution.md`,
`spec/specification.md`, `docs/style-guide.md` — и сам параграф.

Отчёты сохраняются в `reviews/<§>/{deepseek,gpt55-structure,…}.md`
(папка `reviews/` локальная, в git не идёт).

## Обойма редакторов

| Файл-вывод | Модель | Что проверяет |
|------------|--------|----------------|
| `deepseek.md` | DeepSeek | факты о платформе 1С (только техника) |
| `gpt55-structure.md` | GPT | переходы, архитектура текста |
| `gpt55-metaphor.md` | GPT | устойчивость образов под нагрузкой |
| `gpt55-tone.md` | GPT | дыхание, длина предложений (`--tone`) |
| `gpt55-style.md` | GPT | стиль и канон книги (`--style`) |
| `gemini.md` | Gemini | адверсар (ломает тезисы) + читатель |

Промпты ролей — в `scripts/prompts/`. Правьте их под канон конкретной книги.

## Синтез

После прогона **Claude** читает отчёты из `reviews/<§>/` и собирает `synthesis.md`:
сводит замечания, отсеивает противоречивые, предлагает точечные правки. Решение по
каждому параграфу фиксируйте трекером:

```bash
./scripts/status.sh                                  # таблица статусов
./scripts/status.sh detail chapters/.../02-04_*.md   # история
./scripts/status.sh set chapters/.../02-04_*.md approved "готово"
```

Статусы хранятся в `docs/review-status.json` (локальный рабочий файл, не в git).
