# База «Канцтовары» для песочницы запросов

Два файла рядом — учебная база серии в формате песочницы языка запросов
[BSLexicon](https://github.com/iMironRU/BSLexicon) (query-sandbox, формат v1):

- `kanctovary.schema.yaml` — состав базы;
- `kanctovary.data.yaml` — данные.

Песочница забирает их по ссылке, поэтому файлы живут здесь, а не в её
репозитории: база принадлежит книгам серии и меняется вместе с ними.

Прямые ссылки:

```
https://raw.githubusercontent.com/iMironRU/1c-reading-queries/main/assets/sandbox/kanctovary.schema.yaml
https://raw.githubusercontent.com/iMironRU/1c-reading-queries/main/assets/sandbox/kanctovary.data.yaml
```

## Что в базе

Состав взят из «Дерева метаданных 1С» и от книги к книге не меняется. Одно
дополнение — справочник единиц измерения: на нём в третьей главе строится
цепочка точек от строки реализации через товар к его единице.

| объект | назначение |
|---|---|
| `Справочник.Товары` | иерархический: три группы, шесть позиций, одна помечена на удаление |
| `Справочник.Контрагенты` | четверо, у одного ИНН и телефон пусты |
| `Справочник.Склады` | Основной и Дополнительный |
| `Справочник.ЕдиницыИзмерения` | «пач» и «шт»; на них ссылается реквизит товара |
| `Документ.ПоступлениеТоваров` | два, оба проведены |
| `Документ.ПриказОбИзмененииЦен` | два: цены с 1 и с 15 марта |
| `Документ.РеализацияТоваров` | пять, последняя не проведена |
| `РегистрНакопления.ТоварыНаСкладах` | остатки: приход от поступления, расход от реализации |
| `РегистрНакопления.Продажи` | обороты: только продажи |
| `РегистрСведений.ЦеныТоваров` | цена с историей: до 15 марта одна, после — другая; записи пишет проведение приказов |

Период данных — март и апрель 2026 года.

## Синхронность с конфигурацией 1С

Та же база собрана настоящей конфигурацией 1С — в книге о формах,
`config/kanctovary`. Данные у песочницы и у базы 1С одни: **источник — этот
каталог**. Из `kanctovary.data.yaml` генерируется загрузчик, который заливает
данные в 1С и проводит документы, а записи регистров, которые 1С при этом
пишет сама, сверяются с записями здесь — до строки.

Отсюда правило: записи регистров в `kanctovary.data.yaml` не придумываются, а
равны тому, что даёт проведение документов. Поменяли данные или схему —
проверьте:

```bash
# в книге о формах
python3 config/kanctovary/tools/check-sync.py      # быстро, без 1С
bash    config/kanctovary/tools/build-base.sh      # полностью, с 1С и .dt
```

## Числа, на которые опираются параграфы

Бумага А4 на Основном складе — тот самый пример из главы о регистрах:

```
  15.03  Поступление №12   +500
  17.03  Реализация  №47   −200
  19.03  Реализация  №51   −100
                  остаток   200
```

Остатки на конец апреля:

| товар | Основной | Дополнительный |
|---|---|---|
| Бумага А4 | 200 | 200 |
| Ручка шариковая | 300 | — |
| Ручка гелевая | — | 240 |
| Папка-регистратор | 100 | — |

Продано за март: Бумага А4 — 105 000 (два документа), Ручка шариковая — 3 000,
Ручка гелевая — 3 600. Порог `> 100000` из главы о свёртке проходит только
бумага — так и задумано.

## Что песочница пока не отрабатывает

Проверено прогоном запросов книги по этой базе через интерпретатор песочницы
(ветка `claude/modest-grothendieck-37c407`), воспроизводится и на её
собственной демо-базе:

1. **Табличная часть как источник.** `ИЗ Документ.РеализацияТоваров.Товары`
   отдаёт строки документов, а не строк табличной части; поля не находятся.
2. **Виртуальная таблица в соединении.** В `ЛЕВОЕ СОЕДИНЕНИЕ … .Остатки`
   таблица не собирается — приходят движения.
3. **Оборотный регистр.** `.Обороты` у регистра с `view: Обороты` запрещён,
   хотя это единственная его виртуальная таблица.
4. **Унарное `НЕ`** над полем-булевом даёт пусто; `= ЛОЖЬ` работает.
5. **Параметры `&Имя`** всегда пусты — задать значение негде.
6. `ИТОГИ ПО`, `СрезПоследних`, пакеты и `ОБЪЕДИНИТЬ` не реализованы — это
   известные пункты дорожной карты песочницы.
